# Spring Boot 后端代码阅读指南

本项目使用 Java 21、Spring Boot 4 和 Jackson 3。代码保留原来的业务分包、HTTP 路径、JSON 字段、错误状态和统计计算口径。
本轮整理展开了单行方法与无花括号的分支，把区间统计和训练洞察的长流程提取为有明确职责的私有方法，并补充中文 JavaDoc。
Java 源码统一使用 4 空格缩进；简单表达式可以保持一行，多步骤方法、循环及条件分支展开书写。
`pom.xml` 与 `application.properties` 也补充了中文说明，分别用于理解构建配置和运行配置。

## 先理解一次请求

以浏览器请求 `GET /api/activities?limit=12&offset=0` 为例：

```text
Vue fetch('/api/activities?...')
    ↓
ActivityController.list：接收字符串参数，由 Spring 转成 Java 类型，检查范围
    ↓
ActivityService.list：检查数据就绪 → 筛选 → 排序 → 分页 → 新建 JSON 响应
    ↓
ActivityRepository.activities：读取 activities.json；文件未变时复用缓存
    ↓
Controller 返回对象，Spring MVC 使用 Jackson 序列化为 HTTP JSON 响应
```

Controller 声明“请求怎么进入”，Service 处理“业务怎么算”，Repository 封装“数据从哪里读”。
这里的 Repository **不是数据库操作类**，而是本地派生文件的只读访问层。

## 建议阅读顺序

1. `RunningWebgisApiApplication`：理解 `main()` 如何启动 Spring 容器。
2. `config/RunningWebgisProperties`：理解配置绑定和 Java `record`。
3. `activity/ActivityController`：从最短的详情接口读起，再看带多个筛选参数的列表接口。
4. `activity/ActivityService`：理解构造器注入、过滤、Comparator 排序与分页。
5. `activity/ActivityRepository`：理解文件读取、try-with-resources、缓存和路径检查。
6. `common/ApiException`、`ApiExceptionHandler`、`DataReadinessService`：理解异常怎样成为错误响应。
7. `statistics/StatisticsService`：跟着命名方法理解连续日期、滚动窗口和结果组装。
8. `activity/ActivityInsightsService`：理解配速变异系数、心率漂移和分公里计算。
9. `exploration/HeatGridService`：理解预计算网格怎样转换为 GeoJSON。
10. `src/test`：用人工样本和预期响应核对自己对代码的理解。

## 常见注解到底做什么

| 写法 | 在这里的作用 |
| --- | --- |
| `@SpringBootApplication` | 启用自动配置、组件扫描等，启动应用的配置入口 |
| `@RestController` | 注册 HTTP 控制器，将返回对象交给消息转换器输出 JSON |
| `@RequestMapping` | 设置控制器公共路径前缀 |
| `@GetMapping` | 将 GET 请求映射到指定方法 |
| `@RequestParam` | 读取 `?limit=12` 等查询参数，可声明默认值和是否必填 |
| `@PathVariable` | 读取 `/activities/{id}` 路径中的活动 ID |
| `@DateTimeFormat` | 指定查询参数转 LocalDate 时的日期格式 |
| `@Service` | 将业务类注册为 Spring 管理的组件 |
| `@Repository` | 将数据访问类注册为 Spring 管理的组件，表达访问层职责 |
| `@ConfigurationProperties` | 将应用配置绑定为 Java 对象 |
| `@ConfigurationPropertiesScan` | 扫描并注册配置属性类 |
| `@Configuration` | 声明配置类，例如跨域规则 |
| `@RestControllerAdvice` | 为多个控制器提供统一异常处理等能力 |
| `@ExceptionHandler` | 指定某类异常对应的处理方法 |

构造器注入的例子：

```java
public ActivityService(ActivityRepository repository, DataReadinessService readiness) {
    this.repository = repository;
    this.readiness = readiness;
}
```

这表示“要创建 ActivityService，先提供它依赖的两个对象”。Spring 会寻找已注册的组件并传进来。
只有一个构造器时，一般不必再写 `@Autowired`。`final` 只保证依赖引用不被重新赋值，不保证对象内部完全不可变。
单元测试也能自己调用构造器并传入临时数据目录，因此业务代码不必强依赖一个正在运行的服务器。

## 两个复杂业务方法已经拆分

区间统计 `StatisticsService.range()`：

```text
校验日期 → 读取正式跑步及额外 27 天历史
    ↓
buildDailyEntries：补齐没有运动的日期，聚合当天距离、时长和加权心率
    ↓
calculateRollingLoads：计算最近 7 日、28 日负荷及每周基线比
    ↓
buildRangeResponse：仅返回用户选择的日期，组装 summary / daily / weekly
```

注意：月度总览保留所有未被排除的运动；区间训练分析只统计未被排除的 running。
这是迁移代码既有的业务区别，本轮没有统一它们。
相对负荷按分钟数和心率计算；滑动窗口累计原始值，JSON 输出时才舍入，避免重构意外改变数值。
`Daily` 和 `Weekly` 是服务内部的统计对象，不是 Spring Bean、数据库实体或整个应用的全局状态。

训练洞察 `ActivityInsightsService.analyze()`：

```text
读取采样 → 计算配速波动和停顿比例
    ↓
maximumDistance：确定全程距离
    ↓
calculateHeartRateDrift：按距离划分前后半程，比较速度/心率效率
    ↓
classifyTrainingType：用显式 if 分支判断训练类型
    ↓
buildKilometerSplits：聚合分公里指标 → 组装最终 JSON
```

配速是 `1000 / 速度(m/s)`，单位为秒/千米。
前后半程各至少 30 个有效样本才计算漂移；无数据时返回 null，不能把“没有观测”写成真实的零。
训练类型是本项目的规则推测，不等于手表的官方训练分类。

## JavaDoc、行内注释与 Java 类型

- `/** ... */` 放在类、构造器、方法上，是可被 IDE 展示的 JavaDoc。
- `@param` 说明输入的意义、单位和空值约定；`@return` 说明输出；`@throws` 描述调用方需要处理的异常。
- `// ...` 放在算法内部，解释顺序、精度或业务边界，不重复“变量加一”等显然操作。
- `Double` 可以为 null，`double` 不可以；它们在缺失心率等场景含义不同。
- `ObjectNode` 是 JSON 对象，`ArrayNode` 是 JSON 数组，`JsonNode` 是共同父类型。
- Jackson 3 的数据绑定类使用 `tools.jackson.databind` 包名；不要照搬 Jackson 2 教程中的旧导入。
- `record CachedJson(...)` 用来保存缓存元数据；`enum Sort` 将自由字符串限制到支持的排序方式。

共享缓存返回的是可变 JSON 节点，但服务按只读使用。要组装响应，应创建新的 ObjectNode，而不是给缓存中的活动添加临时字段。
缓存按大小和修改时间失效；若外部程序把这两项都保持不变，不能保证识别内容变化。

## 在本机验证

在包含 `pom.xml` 的 `backend_springboot/api` 目录执行：

```bash
./mvnw test
./mvnw package
./mvnw spring-boot:run
```

Windows 对应使用 `mvnw.cmd`。Java 版本以 `pom.xml` 的 `java.version` 为准，目前是 21。
`ServiceRegressionTests` 使用临时目录和人工数据，将各业务响应与重构前保存的 JSON 进行完整比较；测试不会依赖个人 FIT 归档。
同一测试类还验证非法日期、超长统计区间、网格次数越界、非法活动 ID 及轨迹缺失的错误状态。
现有文件缓存测试继续验证文件更新后重新读取，Spring 上下文测试检查依赖能否正确装配。

接口参数类型绑定失败由 Spring MVC 处理；业务范围错误由本项目抛出 ApiException。
因此，不要认为所有无效输入都会经过同一个异常处理器或必定返回相同状态码。
